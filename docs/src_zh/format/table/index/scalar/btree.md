# BTree 索引

BTree 索引是一种两级结构，提供高效的范围查询和排序访问。
它在昂贵的包含所有值的内存结构和昂贵的无法高效搜索的磁盘结构之间取得了平衡。

BTree 的上层设计为缓存在内存中，存储在 BTree 结构（`page_lookup.lance`）中，
而叶子节点通过子索引搜索（`page_data.lance`，目前仅为平面文件）。
这种设计实现了高效的内存使用——例如，对于 10 亿个值，
索引可以存储 256K 个大小为 4K 的叶子节点，BTree 元数据仅需几 MiB 内存
（取决于数据类型），同时将任何搜索范围缩小到仅 4K 个值。

## 存储布局

BTree 索引由两个文件组成：

1. `page_lookup.lance` - BTree 结构，将值范围映射到页码
2. `page_data.lance` - 实际的子索引（平面文件），包含排序后的值和行 ID

### 页查找文件 Schema（BTree 结构）

| 列           | 类型       | 可空 | 描述                                     |
|--------------|------------|------|------------------------------------------|
| `min`        | {DataType} | true | 页中的最小值（构成 BTree 键）              |
| `max`        | {DataType} | true | 页中的最大值（用于范围裁剪）               |
| `null_count` | UInt32     | false| 页中的空值数量                             |
| `page_idx`   | UInt32     | false| 指向 page_data.lance 中子索引的页码        |

### Schema 元数据

| 键 | 类型 | 描述 |
|-----|------|------|
| `batch_size` | String | 每页行数（默认值："4096"） |

### 页数据文件 Schema（子索引）

| 列       | 类型       | 可空 | 描述                              |
|----------|------------|------|-----------------------------------|
| `values` | {DataType} | true | 索引列中的排序值（平面文件）        |
| `ids`    | UInt64     | false| 每个值对应的行 ID                  |

## 加速查询

BTree 索引为以下查询类型提供精确结果：

| 查询类型   | 描述                      | 操作                                                      |
|-----------|---------------------------|-----------------------------------------------------------|
| **Equals** | `column = value`          | BTree 查找相关页面，然后在子索引内搜索                       |
| **Range**  | `column BETWEEN a AND b`  | BTree 遍历与范围重叠的页面，然后搜索每个子索引                |
| **IsIn**   | `column IN (v1, v2, ...)` | 多次 BTree 查找，合并所有匹配子索引的结果                    |
| **IsNull** | `column IS NULL`          | 返回所有 null_count > 0 的页面中的行                        |
