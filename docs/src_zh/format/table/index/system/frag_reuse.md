# 片段复用索引（Fragment Reuse Index）

片段复用索引（Fragment Reuse Index）是一种内部索引，用于在压缩（Compaction）和数据集更新期间优化片段操作。

当对 Lance 表执行数据修改时，可能会同时触发压缩和索引优化，以改善数据布局和索引覆盖率。默认情况下，压缩会同时重映射所有索引以防止读取性能退化。这意味着压缩和索引优化可能会修改同一个索引，导致其中一个进程失败。通常是压缩失败，因为它需要修改所有索引且耗时更长，从而导致表的布局随时间退化。

片段复用索引允许压缩推迟索引重映射过程。假设一次压缩移除了片段 A 和 B 并产生了 C。在查询运行时，它通过将索引中与 A 和 B 相关的行地址更新为 C 中的最新地址来复用旧片段 A 和 B。由于索引通常在初次加载后缓存在内存中，片段复用应用过程完成后，内存中的索引即为最新状态。

## 预期使用模式

如果用户在压缩中推迟了索引重映射，则应创建片段复用索引。每次执行压缩时，该索引会累积一个新的**复用版本（Reuse Version）**。

只要所有标量索引和向量索引都是在特定复用版本之后创建的，这些索引就都是最新的，该特定复用版本就可以被裁剪。

## 影响

### 冲突解决

片段复用索引的存在改变了 Lance 检测并发操作之间冲突的方式。通常会与压缩冲突的操作（如索引构建）在使用 FRI 时可以无冲突地进行。关于冲突检测如何受影响的完整详情，请参见[冲突解决](../../transaction.md#conflict-resolution)。

### 索引加载成本

当 FRI 存在时，索引在加载时必须进行重映射。每次索引被加载到缓存中时，FRI 会被用于将旧行地址转换为当前行地址。这为索引加载增加了少量成本，但索引被缓存后不会影响查询性能。

### FRI 增长与清理

FRI 随着每次压缩而增长。每次推迟索引重映射的压缩都会向索引添加一个新的复用版本。随着时间推移，这会不断累积，增加索引加载的成本，因为需要应用更多的地址转换。

一旦所有标量索引和向量索引都在某个给定的复用版本之后重建，该版本就不再需要，可以被裁剪。用户应安排定期流程来裁剪过时的复用版本，以控制 FRI 的大小。
