# 维护者

维护者是对 Lance 社区做出持续且有价值贡献的贡献者。
维护者因其工作而受到认可，并被授予各种权利以支持其持续贡献。

## 权利 { #rights }

所有维护者拥有以下权利：

- 对所有 Lance 仓库的 GitHub triage 权限
- 随时发布所有 Lance 项目的预览版/测试版
- 提议所有 Lance 项目的稳定版发布
- 在投票通过后执行稳定版发布

部分维护者可能获得 Lance 仓库的 GitHub 写入权限，这允许他们审查和合并拉取请求（Pull Request）。
拥有写入权限的维护者在项目外部沟通时可以自称为 "committer"，
因为这是开源生态系统中广泛认可的术语，
尽管 "committer" 并不是 Lance 官方治理结构的一部分。

拥有 GitHub 写入权限的维护者还拥有以下额外权利：

- 对所有 Lance 仓库的 GitHub 写入权限
- 批准和合并所有 Lance 项目中的代码修改（格式规范变更除外）

## 活动 { #activities }

鼓励维护者：

- 继续为 Lance 项目做出有价值的贡献
- 在可能的情况下帮助审查 PR 并提供反馈
- 在提议稳定版发布时自愿担任发布经理
- 参与社区讨论并支持其他用户
- 指导和培养新的维护者

拥有 GitHub 写入权限的维护者还被鼓励：

- 积极审查和合并 PR，同时维护项目代码质量
- 参与技术讨论和决策
- 维护项目代码标准和最佳实践

## 成为维护者

要成为维护者：

- 做出持续且有价值的贡献
- 表现出积极参与社区的态度
- 由 PMC 成员提名并通过投票批准

以下是一些有价值贡献的示例领域：

- **代码贡献**：
    - 提交实现功能或修复 Bug 的拉取请求
    - 审查代码并对 PR 提供建设性反馈
    - 处理 GitHub 上的问题，特别是标记为 "good first issue" 的问题
- **社区支持**：
    - 在 Discord 和 GitHub Discussions 中帮助其他用户
    - 回答问题并为新人提供指导
    - 主持或参与技术讨论和特别兴趣小组
- **文档和内容**：
    - 编写或改进文档、教程和指南
    - 创建展示 Lance 的博客文章、演示或案例研究
    - 通过文章和技术内容分享你的 Lance 使用经历
- **倡导和推广**：
    - 在聚会、会议或社区活动中介绍 Lance
    - 在社交媒体和开发者平台上传播 Lance
    - 测试新功能并提供详细反馈
    - 在你的组织或社区中推动 Lance 的采用

要获得 GitHub 写入权限，维护者应：

- 展示对 Lance 代码库的深入理解
- 拥有高质量贡献的历史记录
- 赢得社区对代码审查的信任
- 由 PMC 成员提名并通过投票批准
- 签署贡献者许可协议（CLA）
